# Tabula 研究產品定位與分類規範

Tabula 收錄團隊能交到使用者手中的研究成果。**分類的單位是產品，分類的依據是產品支援的研究任務。** 一項研究可以產生多個產品；同一產品也可以來自多項研究。除指名現行目錄的產品外，本文中的產品均為假設例子。

## 先寫清楚產品定位

收錄前，維護者應能用一句話說清楚：「**誰**在**什麼情境**，把**什麼輸入**交給這個產品，得到**什麼可用的結果**？」再說明適用範圍，以及使用者如何取得它。

例如：「實驗研究者輸入歷史批次的量測值與新批次的條件，取得新批次反應值的預測區間，用來決定哪些條件需要補做量測。」這句話能用來判斷產品應歸哪幾類。「一個使用 TFM 的 Python package」只交代了技術與包裝，還缺少使用者要完成的任務。

## 分級：研究方向 → 具名產品

| 層級 | 管理的對象 | 判斷方式 |
| --- | --- | --- |
| 一級：Collection | 一類研究需求的顯示分組，可容納多個產品 | 說清楚這一類服務哪些任務，讓維護者能判斷下一個產品是否適用。分組只登記 id 與英文標籤（`src/data/collection-groups.json`），沒有分類頁面。 |
| 二級：Product | 有明確用途、可獨立取得與使用、有人負責維護的具名成果 | 使用者能選擇這項成果完成一件事，維護者能指出交付物、使用方法及官方來源。每個產品有一個穩定識別碼。 |

產品之下記錄各次**發布**（哪個版本或日期）及其**交付物**（使用者實際取得的套件、權重、CLI 或網頁應用）。版本與交付形式都可增加，不必另設產品類別。論文、資料與評估報告提供依據，可分別關聯到相關產品或版本。

**每個收錄於 Collection 的產品，都必須在自己的產品頁寫使用教學。** 讀者從首頁目錄或側欄點進產品，就能依序完成一次任務：取得或開啟產品、準備範例輸入、執行操作、辨認預期輸出。公開收錄前須備齊這段教學；Notebook 或外部文件可供延伸使用。產品跨類時，各分組列出的是同一頁的直接連結，教學也只維護一份。撰稿時使用[英文產品範本](templates/product.mdx)；檔案位置與分組識別碼約定見[架構文件](architecture.md)。

## 三個初始分組如何判定

分組識別碼為 `models`、`tasks`、`applications`（英文標籤見登記檔，順序即顯示順序）。判準如下：

| Collection | 收錄判準 | 邊界例子 |
| --- | --- | --- |
| **models** | 產品協助使用者完成表格基礎模型的相關工作：交付或適配模型，或準備模型所需的輸入（例如已標記的 context 列與待預測的 query 列）。不要求交付訓練好的模型，但應說明產品支援模型流程的哪一環。 | 為表格基礎模型整理 context/query 輸入的工具可收錄（現行目錄的 Cooling Context 屬此組，本身不是訓練好的模型）；與表格基礎模型無特定關聯的一般資料整理工具，不因同樣處理表格而收錄。 |
| **tasks** | 使用者可直接調用並取得數值結果：指標、估計值、預測區間、檢定或校準評估。應說明結果的計算方式與單位。 | 計算逐批次誤差與整體平均的工具可收錄（現行目錄的 Batch Error 屬此組）；只在開發報告裡列過的數字，留在評估紀錄。 |
| **applications** | 產品把分析能力用於具體的實驗或觀測工作：處理實測批次、比較條件、決定下一步量測。應指出對應的實驗或觀測問題。 | 對實測實驗批次計算誤差、標出需要檢查的批次的工具可收錄（Batch Error 同屬此組）；僅採用科學資料集做通用效能測試，則記為測試資料來源。 |

每個產品至少屬於一組；逐組按其實際支援的任務判定。**符合兩組就直接列在兩組，沒有主次，共用同一份產品紀錄及網址。** 新的使用者需求超出既有範圍時，可新增第四個方向：先寫出該組的收錄判準與邊界例子，在登記檔加入 id 與標籤，再指定適用產品。分組變更不改產品識別碼；跨組統計產品總數時只計一次。

## 如何決定是一個產品、另一個產品，或配套材料

沿用同一產品的情況：用途與維護責任延續，只是演算法升級、增加發布版本，或提供不同的使用入口。若新成果服務可獨立描述的任務，使用者能單獨採用，且團隊會單獨維護與發布，則另建產品紀錄。程式庫是否放在同一個 Git 儲存庫，不決定產品數量。

- **跨類的一個產品**：上述跨批次區間套件既提供統計區間，也服務實驗決策，列入 tasks 與 applications 兩組。若網頁應用只是讓使用者上傳同一份輸入、取得同一結果，它是同一產品的另一個入口。
- **共用技術的兩個產品**：假設團隊另行交付一套實驗排程應用，研究者輸入預算與可用儀器，取得下一輪實驗排程。即使內部調用了上述套件，只要排程應用可獨立採用、維護與發布，就另列一個產品，並記錄其依賴。
- **配套材料**：教讀者調用套件的 Notebook 歸為教學；其中的批次切分、指標與結果歸為該版本的評估紀錄。教學引用的第三方套件標明上游歸屬。

## 收錄後如何維護

維護者保存穩定識別碼、名稱、定位、適用分類及理由、維護者、官方來源、交付形式和發布狀態。公開前核對成果歸屬與公開權限。成熟度獨立於分類：同一類內可同時有試用中、正式發布與已封存的產品。

| 狀態 | 需要記錄的事實 |
| --- | --- |
| `Preview` | 已可試用的能力、取得或申請方式，以及目前限制。只有構想時先保留在研究計畫中。 |
| `Released` | 可取得的交付物、對應版本或發布日期、授權或存取條件，以及能完成一次任務的最小使用例。 |
| `Archived` | 最後發布版本與停止維護的說明；如有接替產品，記錄其去向並保留原紀錄供引用。 |

改版時依官方來源核對交付物，並同步更新產品頁內教學的步驟、範例與適用版本。若報告效能，將結果連到具體版本、資料、切分、指標與出處，讓讀者知道數字是在哪些條件下取得的。
